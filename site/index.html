สคริปต์ FiveM ฟรี ที่ตรวจได้ก่อนลง server

ทุก resource ประกาศใน oss.json อย่างชัดเจนว่าเรียกใช้อะไรบ้าง (HTTP host, command, convar, net event, DB table, file) ทุก PR ถูกตรวจด้วย fivem-devkit safety ทุก release zip ถูกสร้างใน CI พร้อม provenance attestation และ SHA256SUMS โดยคุณสามารถรันคำสั่งตรวจสอบชุดเดียวกันนี้ซ้ำได้ด้วยตัวเอง

ตรวจสคริปต์ของคุณ ดูโค้ดบน GitHub

ตรวจ resource ก่อนลง

คุณสามารถรันคำสั่งนี้เพื่อสแกนโครงสร้างและคำสั่งใน resource โฟลเดอร์ใดก็ได้ก่อนนำไปใส่ server จริง

คำสั่งสแกน
npx @aeterna_game/fivem-devkit safety ./ชื่อโฟลเดอร์

สำหรับสคริปต์ภายนอกที่ไม่มี oss.json ให้ตั้งค่า requireManifest เป็น false ตามรายละเอียดที่อธิบายไว้ใน safety.md

ไฟล์ .fivem-devkit.json ในโฟลเดอร์ที่รันคำสั่ง
{"safety": {"requireManifest": false}}
ตัวอย่างผลจริง (resource ทดสอบ)
✗ [safety/dynamic-load] resources/some_script/server/main.lua:2
    load called — loads code at runtime that nobody reviewed
✗ [safety/host-exec] resources/some_script/server/main.lua:3
    os.execute — runs or changes things on the host machine
✗ [safety/secret-convar] resources/some_script/server/main.lua:4
    GetConvar('mysql_connection_string') reads a secret convar

safety: 3 error(s), 0 warning(s)

ผลลัพธ์จากการสแกนคือรายการจุดในโค้ดที่ต้องเปิดอ่าน ไม่ใช่คำตัดสินว่าโค้ดนั้นทำงานถูกต้องสมบูรณ์หรือไร้ปัญหา

🏗️ Trust Architecture

  1. ผู้เขียน
    source + oss.json
  2. PR gate ใน CI
    devkit check, devkit safety — ใช้เกิน oss.json = PR ล้ม; oss.json ที่เปลี่ยนต้องผ่านการ review ของ CODEOWNERS
  3. release ใน CI
    build zip, provenance attestation, SHA256SUMS
  4. server ของคุณ
    gh attestation verify <zip> --repo aeterna/nakara-oss
    sha256sum -c SHA256SUMS
    npx @aeterna_game/fivem-devkit safety ./resource แล้วค่อย ensure

ด่าน 2–3 เราทำใน CI ด่าน 4 คุณทำซ้ำเองได้ด้วยเครื่องมือตัวเดียวกัน

สิ่งที่ scanner จับไม่ได้

  • logic bomb ที่ซ่อนอยู่ใน API ที่ resource ได้รับอนุญาตให้ใช้
  • การเรียก export ของ resource อื่น
  • server event ที่เชื่อข้อมูลจาก client โดยไม่ตรวจ
  • ค่าที่ประกอบขึ้นตอน runtime: รายงานว่าเจอ แต่ไม่ได้ตามว่าค่าจริงคืออะไร

ยังต้องมีคนอ่านโค้ด

คำถามที่พบบ่อย

ใช้ฟรีไหม
ฟรีทุกตัวภายใต้สัญญาอนุญาต MIT สามารถนำไปใช้งาน ปรับแต่ง หรือแจกจ่ายได้โดยไม่มีค่าใช้จ่าย
สคริปต์ที่ซื้อมาและไม่มี oss.json ตรวจได้ไหม
ได้ ตั้ง requireManifest เป็น false ในไฟล์ .fivem-devkit.json แล้วเครื่องมือจะสแกนหาโค้ดอันตราย (เช่น dynamic-load · host-exec · secret-convar) โดยไม่ต้องมี oss.json
ผลสแกนไม่เจออะไรแปลว่าไม่มีปัญหาไหม
ไม่ ดูรายละเอียดในหัวข้อ สิ่งที่ scanner จับไม่ได้ เครื่องมือนี้ตรวจจับเฉพาะรูปแบบคำสั่งและโครงสร้างที่ระบุไว้เท่านั้น จึงไม่สามารถทดแทนการตรวจสอบโค้ดโดยมนุษย์ได้
ดาวน์โหลด resource ที่ไหน
ดาวน์โหลดได้จากหน้า Releases บน GitHub ของ repo aeterna/nakara-oss เท่านั้น อย่าใช้ปุ่ม Download ZIP ของโค้ดทั้ง repo เพราะไฟล์ release ถูก build ใน CI และมี provenance attestation กับ SHA256SUMS ให้ตรวจ ส่วน ZIP ของ repo มีเทสต์และเครื่องมือที่ server ไม่ต้องใช้
เจอช่องโหว่แจ้งที่ไหน
กรุณาแจ้งผ่านแนวทางใน SECURITY.md ของ repository เท่านั้น เพื่อให้ทีมงานตรวจสอบเป็นการภายใน ห้ามเปิด issue สาธารณะเพื่อแจ้งช่องโหว่
รันบน Windows ได้ไหม
ได้ ต้องมี Node.js 22 ขึ้นไป แล้วรันคำสั่ง npx ใน Command Prompt หรือ PowerShell
