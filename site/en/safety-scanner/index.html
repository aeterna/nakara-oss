fivem-devkit {{devkit.version}}

Check a FiveM script for dangerous code before you install it

Free and open source. Reads code and never runs it. Points at specific lines for you to review, not a verdict.

Quick start

Requires Node.js 22 or newer. To inspect downloaded or purchased scripts that lack an oss.json capability manifest, place a .fivem-devkit.json configuration file in the working directory:

{
  "safety": {
    "requireManifest": false
  }
}

Run the scanner pointing to the script directory:

npx @aeterna_game/fivem-devkit safety ./folder

Real output when dangerous code and backdoor-like patterns are detected:

✗ [safety/dynamic-load] resources/some_script/server/main.lua:2
    load called — loads code at runtime that nobody reviewed
✗ [safety/host-exec] resources/some_script/server/main.lua:3
    os.execute — runs or changes things on the host machine
✗ [safety/secret-convar] resources/some_script/server/main.lua:4
    GetConvar('mysql_connection_string') reads a secret convar

safety: 3 error(s), 0 warning(s)

What it looks for

Rules are divided into hard-deny rules that must never appear in resource code, security and code quality rules, and capability rules checked against oss.json. When requireManifest: false is set, the scanner evaluates hard-deny and quality rules only:

Rule ID What it catches With requireManifest: false
dynamic-load Runtime code execution such as Lua load, loadstring, dofile, loadfile, package.loadlib, JS runtime require/import, or <script src="https://…"> in NUI — the backdoor pattern used to fetch unreviewed code Active
host-exec Host command execution and host filesystem modifications, including os.execute, io.popen, os.remove, os.rename, os.exit, file writing via io.open, or JS child_process and vm Active
host-access Host environment and raw network access, including reading environment variables (os.getenv, process.env), raw sockets (net, dgram, tls), or direct filesystem access through fs Active
code-eval JavaScript code evaluation via eval, Function / new Function, or string execution in setTimeout/setInterval Active
env-tamper Global environment manipulation such as debug.*, getfenv, setfenv, string.dump, _G[computed], or JS globalThis[x] to evade name-based checks Active
invoke-native Calling server-side natives by hash (Citizen.InvokeNative, _in) to bypass capability checks Active
secret-convar Reading secret convars like rcon_password, sv_licenseKey, steam_webApiKey, mysql_connection_string, or names matching token, secret, password, apikey, or webhook (never allowlistable) Active
ace-command Console commands modifying permissions or controlling the server via ExecuteCommand (e.g. add_ace, add_principal, exec, set, rcon, quit, restart, ensure) or runtime command names (never allowlistable) Active
command-injection Server-side ExecuteCommand appending runtime arguments to command strings, risking command injection through ; separators Active
obfuscation Obfuscated patterns designed to bypass inspection, including long escape runs, large base64 strings, repeated string.char calls, or lines over 1,000 characters Active
opaque-file Unreviewable opaque files such as binaries (.dll, .so, .luac), compressed archives (.zip, .rar), or minified JavaScript (*.min.js) Active
nui-html-injection Dynamic HTML assignment in NUI (e.g. innerHTML, outerHTML, document.write) with non-static strings, risking script execution in player clients Active
net-event-rate-limit Server net-event handlers lacking a recognized rate-limiting helper, leaving the event vulnerable to client spam (reported as a warning) Active
missing-manifest Missing oss.json next to fxmanifest.lua or an invalid manifest structure Skipped (needs oss.json)
undeclared-http HTTP requests via PerformHttpRequest, fetch, axios, etc., to destinations not declared in capabilities.http Skipped (needs oss.json)
undeclared-http-handler Handling inbound HTTP requests via SetHttpHandler without declaration in capabilities.httpHandlers Skipped (needs oss.json)
undeclared-command Invoking console commands via ExecuteCommand not declared in capabilities.commands Skipped (needs oss.json)
undeclared-registered-command Registering console or chat commands via RegisterCommand or lib.addCommand not listed in capabilities.registeredCommands Skipped (needs oss.json)
undeclared-convar Reading or setting convars not declared in capabilities.convars Skipped (needs oss.json)
undeclared-net-event Registering server or client net events not declared in capabilities.netEvents Skipped (needs oss.json)
undeclared-nui Using NUI pages, focus natives, or NUI callbacks without setting capabilities.nui: true Skipped (needs oss.json)
undeclared-file-write Writing files via SaveResourceFile without declaring them in capabilities.files.write (writes to other resources are always errors) Skipped (needs oss.json)
undeclared-db Accessing database tables not listed in capabilities.db.tables, or executing DDL without declaring capabilities.db.ddl: true Skipped (needs oss.json)
over-declared Capabilities listed in oss.json that the resource code never actually uses (reported as a warning to prevent silent capability expansion) Skipped (needs oss.json)

Reading the output and allowlisting

Each reported finding displays file:line, the rule ID in brackets [safety/<rule-id>], and a descriptive reason on the line below. These findings point out lines for you to review and inspect manually, rather than acting as an automated verdict.

If you have reviewed the code and confirmed an intentional use case in your environment, you can configure an exception in .fivem-devkit.json:

{
  "safety": {
    "allow": {
      "dynamic-load": [
        { "path": "resources/my_pkg/server/catalog.lua", "reason": "loads catalog.lua shipped in this resource into an empty env" }
      ]
    }
  }
}

Rules for allowlisting:

  • Every entry must supply a specific path (relative to the project root or resource folder) and a clear reason.
  • Catch-all paths like *, **, or . are rejected with invalid-allow.
  • Rules that can never be allowlisted: secret-convar and ace-command cannot be exempted under any circumstance. Allowing credential reads exposes database passwords and API keys, while allowing ACE command execution grants complete server takeover capabilities. Any allowlist entry targeting them is rejected with invalid-allow.

What it cannot catch

  • Logic bombs inside allowed APIs: A resource declared to access db.tables: ["players"] can drop or wipe player records on a specified date. An endpoint declared for HTTP can transmit arbitrary payloads.
  • Abuse through other resources' exports: Invocations like exports.some_admin:giveAdmin(src) look like normal export calls; the scanner cannot judge what external resources expose.
  • Trusting the client: Server net events that hand out items or money to any client caller remain severe vulnerabilities even when declared and rate limited.
  • Data-dependent behaviour / values built at runtime: URLs, commands, or convar names assembled dynamically are flagged as dynamic values, but their runtime values cannot be traced.
  • Native calls by hash or unlisted names: Client-side natives invoked by hash, or new engine capabilities added to FiveM after the scanner was built.

A human still has to read the code: A scan with zero errors indicates only that automated checks found no violations, not that the code is free from risk. Server owners must always inspect and review code manually.

For resource authors

Every resource declares its required capabilities in an oss.json manifest (validated against oss.schema.json), explicitly listing its HTTP endpoints, console commands, convars, net events, database tables, and file writes. Declaring exact capabilities informs server owners before installation, and CI runs fivem-devkit safety on every Pull Request to ensure the code never accesses anything undeclared. For configuration details, see the safety.md documentation.
