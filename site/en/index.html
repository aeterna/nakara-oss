Free FiveM scripts you can check before they touch your server

Every resource declares in oss.json what it touches (HTTP host, command, convar, net event, DB table, file); every PR is scanned by fivem-devkit safety; every release zip is built in CI with a provenance attestation and SHA256SUMS; you can re-run the same checks yourself.

Scan your script Code on GitHub

Check a resource before you install it

Run this command to inspect any resource folder before deploying it to your server:

Scan command
npx @aeterna_game/fivem-devkit safety ./your_folder

For a script from elsewhere with no oss.json, configure safety.md options:

.fivem-devkit.json in the folder you run from
{
  "safety": {
    "requireManifest": false
  }
}

🏗️ Trust Architecture

  1. Author
    source + oss.json
  2. PR gate in CI
    devkit check, devkit safety — using more than oss.json = PR fails; oss.json changes need CODEOWNERS review
  3. Release in CI
    build zip, provenance attestation, SHA256SUMS
  4. Your server
    gh attestation verify <zip> --repo aeterna/nakara-oss
    sha256sum -c SHA256SUMS
    npx @aeterna_game/fivem-devkit safety ./resource
    then ensure

Steps 2–3 run in our CI. Step 4 you repeat yourself with the same tools.

What the scanner cannot catch

  • A logic bomb inside an API the resource is allowed to use
  • Calls to other resources' exports
  • A server event that trusts the client
  • Values built at runtime (reported where they occur, but not traced)

A person still has to read the code.

Questions

Is it free?
Yes, everything is free under the MIT license. You can use, modify, and distribute all resources without cost.
Can I scan a script I bought that has no oss.json?
Yes. Set requireManifest to false in .fivem-devkit.json. The scanner still finds dangerous code such as dynamic-load, host-exec, and secret-convar.
The scan found nothing. Is the script fine?
No. See What the scanner cannot catch. The tool looks for known patterns and does not replace reading the code.
Where do I download resources?
Only from GitHub Releases, not the repo ZIP. Release files are built in CI with a provenance attestation and SHA256SUMS; the repo ZIP carries tests and tooling a server does not need.
Where do I report a vulnerability?
Follow SECURITY.md in the repository, never open a public issue.
Does it run on Windows?
Yes, with Node.js 22 or newer, from Command Prompt or PowerShell.
