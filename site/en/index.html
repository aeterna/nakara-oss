01

Say there is no oss.json

// .fivem-devkit.json { "safety": { "requireManifest": false } }

Scan

🏗️ Trust Architecture

What one piece of code passes before it reaches your server

The orange crate declares what its code does, so it passes every gate to your machine. The grey crate calls an HTTP host it never declared, so the first gate stops it. Gates two and three run in our CI. The last one you repeat yourself.

Declares what its code does: passes the PR gate, gets an attestation at release, three re-checks, then ensure Calls an undeclared HTTP host: devkit safety stops it, the PR fails, no release

Limits

What the scanner cannot catch

The scanner shows that code only uses what it declares. It cannot tell whether it uses that honestly

A logic bomb inside an allowed APIa resource that declares db.tables: ["players"] can delete every row on a set date
Calls to other resources' exportsexports.some_admin:giveAdmin(src) looks like any other export call
A server that trusts the clientan event that gives items to whoever asks is declared, rate limited and still an exploit
Values built at runtimereported where they occur, but not traced

A person still has to read the code

Questions

Common questions

Is it free?

Yes, everything is MIT.

Can I scan a script I bought that has no oss.json?

Yes. Set requireManifest to false in .fivem-devkit.json and it still finds dangerous code such as dynamic-load, host-exec and secret-convar.

The scan found nothing. Is the script fine?

No. See what the scanner cannot catch. It looks for known patterns and does not replace reading the code.

Where do I download resources?

Only from GitHub Releases. Release files are built in CI with a provenance attestation and SHA256SUMS; the repo ZIP carries tests and tooling a server does not need.

Where do I report a vulnerability?

Follow SECURITY.md in the repo, never a public issue.
