ตรวจสคริปต์ FiveM หาโค้ดอันตราย ก่อนลง server

เครื่องมือฟรี โอเพนซอร์ส อ่านโค้ดโดยไม่รันโค้ด ชี้ตำแหน่งและบรรทัดที่ควรเปิดอ่านด้วยตนเอง ไม่ใช่คำตัดสิน

วิธีเริ่มใช้งานอย่างรวดเร็ว

บนเครื่องที่ติดตั้ง Node.js 22 ขึ้นไป หากคุณต้องการตรวจสคริปต์ที่ดาวน์โหลดหรือซื้อมาจากภายนอกซึ่งไม่มีไฟล์ oss.json ให้สร้างไฟล์คอนฟิก .fivem-devkit.json ไว้ในโฟลเดอร์ที่ต้องการรัน:

{
  "safety": {
    "requireManifest": false
  }
}

จากนั้นรันคำสั่งสแกนระบุโฟลเดอร์ของสคริปต์:

npx @aeterna_game/fivem-devkit safety ./folder

ตัวอย่างผลลัพธ์จริงเมื่อพบโค้ดอันตรายและโค้ดแบบที่ backdoor ใช้:

✗ [safety/dynamic-load] resources/some_script/server/main.lua:2
    load called — loads code at runtime that nobody reviewed
✗ [safety/host-exec] resources/some_script/server/main.lua:3
    os.execute — runs or changes things on the host machine
✗ [safety/secret-convar] resources/some_script/server/main.lua:4
    GetConvar('mysql_connection_string') reads a secret convar

safety: 3 error(s), 0 warning(s)

เครื่องมือตรวจหาอะไรบ้าง

กฎการตรวจแบ่งออกเป็นกลุ่มกฎเด็ดขาด (Hard deny) ที่ไม่อนุญาตให้มีในโค้ด, กฎคุณภาพและความมั่นคงปลอดภัย, และกลุ่มกฎสิทธิ์ (Capabilities) ที่ตรวจสอบเทียบกับไฟล์ oss.json โดยเมื่อตั้งค่า requireManifest: false เครื่องมือจะตรวจเฉพาะกฎเด็ดขาดและกฎคุณภาพ:

รหัสกฎ คำอธิบายความเสี่ยง สถานะเมื่อ requireManifest: false
dynamic-load การโหลดโค้ดมารันตอน runtime เช่น Lua load, loadstring, dofile, loadfile, package.loadlib หรือ JS dynamic require/import และ <script src="https://…"> ใน NUI ซึ่งเป็นโค้ดแบบที่ backdoor ใช้ดึงโค้ดที่ไม่มีใครเคยตรวจมารัน ตรวจ
host-exec การสั่งรันคำสั่งบนเครื่อง host หรือดัดแปลงไฟล์ของเครื่อง เช่น os.execute, io.popen, os.remove, os.rename, os.exit, การเปิดไฟล์เขียนด้วย io.open หรือ JS child_process, vm ตรวจ
host-access การเข้าถึงระบบนอกขอบเขต เช่น อ่าน Environment Variable (os.getenv, process.env), การเปิด raw socket (net, dgram, tls) หรือเข้าถึง filesystem ตรงผ่าน fs ตรวจ
code-eval การ eval โค้ดใน JavaScript เช่น eval, Function / new Function หรือส่ง string เข้า setTimeout/setInterval ตรวจ
env-tamper การแทรกแซง global environment เช่น debug.*, getfenv, setfenv, string.dump, _G[computed] หรือ JS globalThis[x] เพื่อหลบเลี่ยงการตรวจจับชื่อฟังก์ชัน ตรวจ
invoke-native การเรียก native ฝั่ง server ผ่าน hash (Citizen.InvokeNative, _in) เพื่อหลบเลี่ยงการตรวจชื่อ native ที่ใช้ควบคุม server ตรวจ
secret-convar การอ่าน convar เก็บความลับ เช่น rcon_password, sv_licenseKey, steam_webApiKey, mysql_connection_string หรือ convar ที่มีคำว่า token, secret, password, apikey, webhook (กฎนี้ไม่อนุญาตให้ allowlist) ตรวจ
ace-command การสั่งคำสั่งคอนโซลจัดการสิทธิ์หรือควบคุม server ผ่าน ExecuteCommand เช่น add_ace, add_principal, exec, set, rcon, quit, restart, ensure หรือชื่อคำสั่งที่สร้างตอน runtime (กฎนี้ไม่อนุญาตให้ allowlist) ตรวจ
command-injection การใช้ ExecuteCommand ฝั่ง server โดยนำค่า runtime มาต่อท้ายชื่อคำสั่ง ซึ่งเสี่ยงต่อการโดนแทรกคำสั่งที่สองผ่านเครื่องหมาย ; ตรวจ
obfuscation โค้ดที่จงใจอำพรางให้อ่านยาก เช่น escape sequence ยาวผิดปกติ, base64 ก้อนใหญ่, การต่อตัวเลขด้วย string.char หรือบรรทัดที่ยาวเกิน 1,000 ตัวอักษร ตรวจ
opaque-file ไฟล์ทึบแสงที่คนไม่สามารถเปิดอ่านโค้ดได้ เช่น ไฟล์ binary (.dll, .so, .luac), ไฟล์บีบอัด (.zip, .rar), หรือ JavaScript ที่ถูกบีบอัด minified (*.min.js) ตรวจ
nui-html-injection การกำหนดค่า HTML ใน NUI ด้วยตัวแปรที่ไม่ใช่ string คงที่ เช่น innerHTML, outerHTML, document.write เสี่ยงต่อการโดนโจมตีรันสคริปต์บนเครื่อง client ทุกคนที่เห็น ตรวจ
net-event-rate-limit server net event handler ที่ไม่ได้เรียกใช้ฟังก์ชันจำกัดอัตรา (rate limit) ที่รู้จัก เพื่อป้องกันไม่ให้ client ยิง event ถี่เกินไปจนกระทบ server (รายงานเป็น warning) ตรวจ
missing-manifest ไม่มีไฟล์ oss.json คู่กับ fxmanifest.lua หรือโครงสร้างไฟล์ไม่ถูกต้อง ข้าม (ต้องมี oss.json)
undeclared-http การยิง HTTP ผ่าน PerformHttpRequest, fetch, axios ไปยังปลายทางที่ไม่ได้ประกาศใน capabilities.http ข้าม (ต้องมี oss.json)
undeclared-http-handler การดักรับ HTTP request ด้วย SetHttpHandler โดยไม่ได้ประกาศใน capabilities.httpHandlers ข้าม (ต้องมี oss.json)
undeclared-command การเรียกใช้คำสั่งคอนโซลผ่าน ExecuteCommand โดยไม่ได้ประกาศใน capabilities.commands ข้าม (ต้องมี oss.json)
undeclared-registered-command การลงทะเบียนคำสั่งด้วย RegisterCommand หรือ lib.addCommand โดยไม่ได้ระบุใน capabilities.registeredCommands ข้าม (ต้องมี oss.json)
undeclared-convar การอ่านหรือเขียน convar ที่ไม่ได้ระบุไว้ใน capabilities.convars ข้าม (ต้องมี oss.json)
undeclared-net-event การลงทะเบียน net event ที่ไม่ได้ระบุใน capabilities.netEvents ข้าม (ต้องมี oss.json)
undeclared-nui การใช้งาน NUI (เช่น ui_page, SetNuiFocus, NUI callbacks) โดยไม่ได้เปิด capabilities.nui: true ข้าม (ต้องมี oss.json)
undeclared-file-write การเขียนไฟล์ด้วย SaveResourceFile โดยไม่ได้ประกาศใน capabilities.files.write (การเขียนข้ามไป resource อื่นถือเป็นข้อผิดพลาดเสมอ) ข้าม (ต้องมี oss.json)
undeclared-db การเข้าถึงตารางฐานข้อมูลที่ไม่ได้ระบุใน capabilities.db.tables หรือใช้คำสั่ง DDL โดยไม่ได้ระบุ capabilities.db.ddl: true ข้าม (ต้องมี oss.json)
over-declared การประกาศ capability ใน oss.json ไว้แต่ในโค้ดไม่มีการเรียกใช้งานจริง (รายงานเป็น warning เพื่อไม่ให้เปิดช่องโหว่ทิ้งไว้) ข้าม (ต้องมี oss.json)

วิธีอ่านผลลัพธ์และการยกเว้น

ผลลัพธ์แต่ละบรรทัดจะระบุ ไฟล์:เลขบรรทัด, รหัสกฎในวงเล็บ [safety/<rule-id>] และข้อความอธิบายเหตุผลด้านล่าง รายการเหล่านี้คือตำแหน่งที่ผู้ดูแลระบบควรเปิดอ่านโค้ดจริงเพื่อตรวจสอบเจตนา ไม่ใช่คำตัดสินขั้นสุดท้าย

หากคุณตรวจสอบโค้ดแล้วพบว่าเป็นโค้ดที่ตั้งใจใช้งานจริงในสภาพแวดล้อมของคุณ สามารถตั้งค่าข้อยกเว้น (allowlist) ใน .fivem-devkit.json ได้ดังนี้:

{
  "safety": {
    "allow": {
      "dynamic-load": [
        { "path": "resources/my_pkg/server/catalog.lua", "reason": "loads catalog.lua shipped in this resource into an empty env" }
      ]
    }
  }
}

ข้อกำหนดในการยกเว้น:

  • ทุกรายการต้องระบุ path (ตรงกับพาธไฟล์หรือ prefix) และระบุ reason อธิบายเหตุผลอย่างชัดเจน
  • ไม่อนุญาตให้ใช้ wildcard ครอบคลุมทั้งหมด เช่น *, ** หรือ . (จะถูกปฏิเสธด้วย invalid-allow)
  • กฎที่ไม่สามารถขอยกเว้นได้เด็ดขาด: secret-convar และ ace-command จะไม่สามารถใส่ใน allowlist ได้ เพราะการอนุญาตให้อ่าน secret convar จะทำให้กุญแจสำคัญของ server รั่วไหล และการอนุญาตคำสั่ง ACE จะทำให้สคริปต์สามารถยึดสิทธิ์ผู้ดูแลระบบของ server ได้ทันที

สิ่งที่เครื่องมือไม่สามารถตรวจจับได้

  • logic bomb ใน API ที่ได้รับอนุญาต: สคริปต์ที่ประกาศสิทธิ์เข้าถึงฐานข้อมูล db.tables: ["players"] สามารถสั่งลบข้อมูลผู้เล่นทั้งหมดเมื่อถึงวันที่กำหนดได้ หรือสคริปต์ที่ได้รับอนุญาตให้เรียก HTTP ก็สามารถส่งข้อมูลใดๆ ออกไปได้
  • การเรียก export ของ resource อื่น: คำสั่งอย่าง exports.some_admin:giveAdmin(src) มีรูปแบบเหมือนการเรียก export ทั่วไป เครื่องมือไม่สามารถล่วงรู้ได้ว่า resource ปลายทางอนุญาตให้ทำอะไรบ้าง
  • server ที่เชื่อ client: server net event ที่แจกเงินหรือไอเทมให้ทุกคนที่ส่งคำขอเข้ามา แม้จะประกาศสิทธิ์ครบและมี rate limit แล้ว ก็ยังคงเป็นช่องโหว่ทางตรรกะ
  • ค่าที่ประกอบขึ้นตอน runtime: URL คำสั่ง หรือชื่อ convar ที่ต่อ string จากตัวแปรตอน runtime เครื่องมือจะแจ้งเตือนว่าสร้างตอน runtime แต่ไม่สามารถตามรอยวิเคราะห์ค่าจริงได้
  • การเรียก native ด้วย hash หรือชื่อที่ไม่ได้อยู่ในรายการ: เช่น native ฝั่ง client ที่เรียกด้วย hash หรือความสามารถใหม่ๆ ที่ FiveM อาจเพิ่มขึ้นในอนาคต

ยังต้องมีคนอ่านโค้ด: ผลการสแกนที่ไม่พบข้อผิดพลาดหมายถึงไม่มีสิ่งที่ระบบอัตโนมัติตรวจคัดค้าน ไม่ได้แปลว่าโค้ดไม่มีความเสี่ยง ผู้ดูแล server ยังจำเป็นต้องเปิดอ่านและตรวจสอบโค้ดด้วยตนเองเสมอ

สำหรับผู้พัฒนา resource

ทุก resource ในโครงการประกาศรายการสิทธิ์ที่ตนเองต้องใช้ไว้ในไฟล์ oss.json (ดูข้อกำหนดที่ oss.schema.json) ตั้งแต่ URL สำหรับ HTTP, คำสั่ง console, convar, net event ไปจนถึงตารางฐานข้อมูลและไฟล์ การประกาศตรงตามความเป็นจริงช่วยให้ผู้ดูแล server ทราบล่วงหน้าว่าสคริปต์จะเข้าถึงอะไรบ้าง และระบบ CI จะใช้ fivem-devkit safety ตรวจสอบทุก Pull Request ว่าไม่มีการเข้าถึงสิ่งที่ไม่ได้ประกาศ อ่านรายละเอียดและตัวเลือกทั้งหมดได้ใน เอกสาร safety.md
