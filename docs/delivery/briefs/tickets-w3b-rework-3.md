2. `apps/server/test/me.test.ts` › "placeholder row calls /guilds/{id} once…": `expected [..] to have a length of 1 but got 2`. The second call is not from `me.ts`: the staff check in `apps/server/src/staff.ts` (line ~66) also fetches `https://discord.com/api/v10/guilds/{id}` to read `owner_id`. Keep the product as is; make the test say what it means: on the first request, `me.ts` adds exactly one `/guilds/{id}` call beyond the staff check (count the staff-check call separately, e.g. by asserting 2 and naming both in a comment, or by pre-warming the staff cache before the request). The second request must still make no fetch at all.

Wait until the `# ticket-drop` option is present (e.g. `await screen.findByRole('option', { name: '# ticket-drop' })`) before changing it. If the save is still blocked by form validation (e.g. the default button needs a category), select the mock category for the button in the test; do not change `Panels.tsx` unless it truly drops a selected channel, and say which it was.
