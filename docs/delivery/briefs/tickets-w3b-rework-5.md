# tickets W3b rework 5 — Q3 (Sonnet) findings: 1 major + 4 minors
Repo nakara-oss, project `tickets/` (vitest). Write the failing test first, then the fix. Use your file editing tools only; do not run shell commands. Edit only files in the scope. Keep the change to these items.

1. (major) Editing a category cannot clear emoji, welcome message or auto-close hours: `apps/web/src/pages/Categories.tsx` (~111-124) leaves those keys out when blank, and `packages/db/src/queries/categories.ts` (~77-103) treats `undefined` as unchanged. Send `null` for a blank emoji, welcome message and auto-close; make `welcomeMessage` `.nullable()` in `categoryInputSchema` (`apps/server/src/routes/categories.ts`), in `tickets/openapi.yaml` (CategoryInput and Category) and in the web types (`apps/web/src/types.ts`); the db query stores `null`. Tests: server PUT with nulls clears the three fields (`apps/server/test/categories.test.ts`); web edit with emptied fields sends nulls (`apps/web/test/categories.test.tsx`).
2. `formatCategory` (routes/categories.ts ~37-55): `welcomeMessage`/`form` may be null — mark them nullable in openapi Category and the web type (consistent with item 1); and drop the `createdAt` fallback to `new Date()` (use the row's `created_at` only).
3. `gameServerId` on category create/update is not checked against the guild. In the route, when `gameServerId` is set, verify the server exists in this guild (`gameServers` table, `inGuild`, not revoked if that column exists) else 400 `{ code: 'invalid', message: 'unknown game server' }`. Test in categories.test.ts with another guild's server id.
4. `apps/server/src/routes/me.ts` (~68-90): while a guild name is still the placeholder, every `/me` blocks on Discord `/guilds/{id}` (10 s timeout) even when it keeps failing. Add a module-level negative cache: after a failed lookup for a guild, skip the lookup for 60 s (bounded map, at most 200 guilds). Test in `apps/server/test/me.test.ts`: failing lookup → second request within 60 s makes no `/guilds/{id}` call from me.ts (staff check calls are separate, see the comment already in that test).
5. `apps/web/src/pages/GameServers.tsx` (~81-120): the polling compares against `servers` captured when the effect starts; if the list was not loaded yet, any existing server counts as new and the pair dialog closes at once. Take the baseline from a fresh `getGameServers` call when polling starts (before the first comparison). Test in `apps/web/test/servers.test.tsx`.
