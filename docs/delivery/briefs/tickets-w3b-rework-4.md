Repo nakara-oss. Use your file editing tools only; do not run shell commands. Edit only files in the scope. Follow `.aeterna/engineer.md`. Fix exactly the causes below.

1. Resource `packages/tickets/server/js/*.js`: `spec/require-paths.test.js` › "server scripts load with FXServer resource-root require resolution" fails with `Cannot find module '/…/packages/tickets/pairing.js'`. Cause: `isMissingSpecifier(err, specifier)` (added in run 20261120-221937-ea8175) checks that the error message contains `'./pairing.js'`, but Node — and FXServer — put the RESOLVED absolute path in the message (`Cannot find module '/abs/resource/pairing.js'`), so the fallback never runs and the resource would fail to load on a real server. Match the specifier with its leading `./` replaced by `/` as a path suffix inside the quoted name (e.g. `'./pairing.js'` → the message's quoted path ends with `/pairing.js`), and also accept the bare specifier text; a missing nested dependency (a different file name) must still be rethrown. Change every copy of the helper the same way.
2. `spec/minors.test.js` uses `actionsMod._loadSibling` (TypeError: not a function) — rework 2 removed that export. Put `_loadSibling: loadSibling` back in `server/js/actions.js` exports, and add a spec case for item 1: a MODULE_NOT_FOUND whose message is `Cannot find module '/x/y/pairing.js'` falls back; one naming `/x/y/other.js` is rethrown.
3. `tickets/apps/web/test/panels.test.tsx` › "saves panel with target channel selected via ChannelSelect" still fails (`Unable to find role="option" name "# ticket-drop"`). Cause: the test's fetch mock returns `headers: new Headers()` with no content type; `apps/web/src/api.ts` `request()` parses JSON only when `content-type` includes `application/json`, so every mocked response is read as text and the channel list never loads. Give each mocked response in that test `headers: new Headers({ 'content-type': 'application/json' })`. Product code stays as is.
